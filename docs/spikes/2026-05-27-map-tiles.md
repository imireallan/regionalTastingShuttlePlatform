## Question

Can MapLibre reliably render the target shuttle region without production use of `tile.openstreetmap.org`?

## What this spike tests

| Test focus | What we need to learn |
|---|---|
| OpenFreeMap render baseline | Whether map shell loads cleanly with OpenFreeMap Liberty by default. |
| Provider swapping | Whether map style can switch without rewriting map business logic. |
| Overlay separation | Whether route/stops/shuttle overlays remain independent from tile provider. |
| Weak network behavior | Whether shuttle overlay updates can visibly degrade while map shell remains intact. |
| Evidence capture | Whether load/error/update telemetry can be exported for review. |
| Banned host rule | Whether `tile.openstreetmap.org` is absent from spike map config and logs. |

## Decision

## Recommendation

| Production choice | Recommendation |
|---|---|
| Renderer | Use MapLibre GL JS. |
| V1 default provider | Use OpenFreeMap (`styles/liberty`) unless field tests show instability. |
| Provider abstraction | Keep provider config in a single map config module to enable fallback swap (MapTiler or self-hosted PMTiles). |
| Overlay architecture | Keep shuttle GPS and stop overlays independent from base style provider. |
| Monitoring | Capture map load/error telemetry in app logs for early production days. |

## Implementation impact

| Area | Likely impact |
|---|---|
| Frontend map module | Add provider config map (style IDs/URLs) and runtime switch support. |
| Rider map | Render route/stops/active shuttle as separate data sources/layers. |
| Admin live ops map | Reuse same provider abstraction and overlay patterns. |
| Ops runbook | Add provider fallback procedure for tile outages/spikes. |
